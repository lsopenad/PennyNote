# Auditoría de noviembre de 2026

Auditoría de dead code, redundancia y rendimiento en ejecución. Se entrega en tres PRs:

1. ~~Quitar el modo demo y añadir `DebugSeed`~~: fusionada en lsopenad/PennyNote#14.
2. Dead code y redundancia (este bloque).
3. Rendimiento, medido con datos sintéticos de 1k, 10k y 50k gastos (pendiente).

Criterios acordados:

- **Dead code:** se usa Periphery en local. Lo que solo usan los tests o los previews se decide caso a caso.
- **Redundancia:** solo se unifican duplicados reales con el mismo significado. Las vistas que se parecen pero tienen otro propósito se quedan separadas.

## 2. Dead code y redundancia

Herramientas:

- Periphery 3.8.0 sobre el esquema `PennyNote` (app, widget y tests), conservando los `#Preview`.
- Las claves de los String Catalogs, cruzadas con las `.stringsdata` que genera la compilación.
- Búsqueda manual de formateadores, cálculos por mes y día, sumas y agrupaciones repetidas.

En resumen, el código está limpio: no hay TODO/FIXME ni código comentado, Periphery solo encuentra dos símbolos muertos de verdad y el catálogo no tiene claves sobrantes.

### Para la PR 3 (rendimiento)

Estos puntos no son redundancia, pero conviene medirlos:

- `AppCurrency.symbol` crea un `NumberFormatter` en cada llamada. Se usa en `AmountField` y en `displayName`, que aparece en la lista de monedas y en Ajustes.
- `StatisticsView` calcula `SpendingStatistics.dailyTotals` para el resumen y otra vez para la gráfica.
- `ExpenseListView` y `FilteredExpensesView` cargan todos los gastos activos con `@Query` y filtran en memoria en cada evaluación de `body`.
